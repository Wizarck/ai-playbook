# Design — slice-5b-concepts-rewrite

## Architecture

Concept docs become a schema-validated, anchor-stable reference corpus that the rest of Slice 5 (5.A rules, 5.C runbooks, 5.D tutorials, 5.E new process rules) cross-references deterministically.

```
docs/concepts/
├── INDEX.md                          (auto-generated by gen_indexes.py — not in scope here)
├── STYLE.md                          (authoritative exemplar — refined here)
├── enforcement-layers.md             (placeholder → real content)
├── cross-llm-activation.md           (placeholder → real content)
├── enforcement-pairing-exceptions.md (placeholder → real content)
├── taxonomy.md                       (placeholder → real content)
└── <~53 other concept docs>          (frontmatter injection + RFC-2119 softening)
```

## Discriminator: rules vs concepts (D4 + D9)

The two schemas are disjoint by construction:

- `schemas/schema-rule-v1.json` REQUIRES `paired_hardrule:`, `activation:`, `status:`. Forbids them missing.
- `schemas/schema-concept-v1.json` REQUIRES `schema: concept/v1`, `slug:`, `title:`. Forbids `paired_hardrule:`, `activation:`, `status:` via `additionalProperties: false`.

A concept doc that needs RFC 2119 vocabulary in its body is a misclassified rule. The rewrite treats RFC 2119 in body prose as a smell signal:

1. If the softened form (`must` → `is required to`) keeps the meaning intact ⇒ soften.
2. If softening loses the binding-clause meaning ⇒ leave the keyword AND log the passage in `flagged-for-rule-migration.md`.

Slice 5.A consumes that flag list as its input queue.

## Anchor-naming convention

Cross-reference contract for 5.A/C/D/E:

- Concept docs are addressed as `docs/concepts/<slug>.md#<section-slug>`.
- The frontmatter `slug:` field is the **authoritative identifier** (D3); filename derives from slug, not the reverse.
- Section headings within a concept doc use kebab-case anchors generated by the markdown renderer; for cross-doc cites use the document slug only (`docs/concepts/<slug>.md`) unless the citing slice needs a specific section.

Renames after this PR merges break 5.A/C/D/E. Treat the slug list as a contract surface.

## Frontmatter shape (per schemas/schema-concept-v1.json)

```yaml
---
schema: concept/v1
slug: <kebab-case-matching-filename>
title: <human-readable, ≤200 chars>
summary: |
  <optional, ≤500 chars, multi-line allowed>
tags: [<optional list>]
last_validated: 2026-05-19  # optional, ISO date
---
```

Fields FORBIDDEN by `additionalProperties: false`: `paired_hardrule`, `activation`, `status`, `triggers`, `break_glass`, `applies_to`, `globs`, `rule_bundle`. Any of these in a concept doc indicates misclassification.

## "Flag, don't move" rule

Sub-slice 5.B does NOT physically move content from `docs/concepts/` to `docs/rules/`. That is 5.A's job (parallel sub-slice). 5.B only:

1. Identifies passages that should be rules.
2. Logs them with sufficient context (source path, section, suggested target rule filename, 1-line rationale).
3. Leaves the original content in place so 5.A can extract it deterministically without rebase pain.

The flag file is `openspec/changes/slice-5b-concepts-rewrite/flagged-for-rule-migration.md`. 5.A reads it.

## Out of scope

- `docs/rules/*.rule.md` rewrites (Sub-slice 5.A).
- `docs/runbooks/*.md` rewrites (Sub-slice 5.C).
- `docs/tutorials/*.md` rewrites (Sub-slice 5.D).
- New process-rule creation (Sub-slice 5.E).
- Cross-folder link-integrity passes (Sub-slice 5.F harmonisation).
- VERSION bump + CHANGELOG entry (Sub-slice 5.F).
- Hardening `scripts/validate_pairing.py` from warn to fail (Sub-slice 5.F).

## Risks

- **Risk: RFC 2119 softening loses meaning silently.** Mitigation: any softening that feels lossy gets the original keyword preserved AND a flag entry in `flagged-for-rule-migration.md`. Human spot-check at PR review.
- **Risk: anchor list is unstable.** Mitigation: this slice merges BEFORE 5.A/C/D/E branch off. The PR body lists every locked slug as a contract surface.
- **Risk: oversized docs blow the 300-line cap (D7).** Mitigation: this slice does not split docs (would be a refactor outside scope). Oversized docs are flagged in `flagged-for-rule-migration.md` under a "needs-split" subsection for 5.F to triage; the 300-line cap is enforcement-deferred to 5.F when validators flip to strict.
